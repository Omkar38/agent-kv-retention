# Week 4 datasets — validated TraceLab pause handoff

These two Parquet artifacts connect **round-gap pause extraction** with **timing, attribution, and quality checks**. They are designed for the next stage of *Learning-Augmented KV-Cache Retention for Tool-Using LLM Agents*: pause-duration prediction and error analysis.

## Files

| File | Rows (first validated run) | Purpose |
|---|---:|---|
| `pauses_v2.parquet` | **357,161** | Full Brian-derived pause table, augmented with source-round timing checks, quality reasons and conservative eligibility flags. Preserves originally unusable and ambiguous rows for auditing. |
| `week4_pause_train.parquet` | **219,465** | Strict single-tool **inter-round pause-duration proxy** cohort for the initial Week 4 predictor: 105,395 Claude and 114,070 Codex records. |

The artifacts are generated by [`../validation/build_pause_handoff.py`](../validation/build_pause_handoff.py).
### Prediction schema

`week4_pause_train.parquet` has these intended columns:

| Column | Role |
|---|---|
| `provider` | Source/provider; optional model feature and distribution-shift grouping |
| `session_id` | Train/validation/test grouping only; **never an ordinary prediction feature** |
| `round_index` | Step metadata; use only after confirming observability |
| `split` | Deterministic session-level `train`, `val`, or `test` partition; **not a predictor input** |
| `tool_name_at_decision` | Primary candidate feature, matched to a tool emitted in the source round |
| `tool_input_chars_at_decision` | Primary candidate feature |
| `target_pause_s` | **Label** (seconds): Brian-style inter-round waiting proxy; never an input feature |

The full `pauses_v2.parquet` additionally contains original Brian fields, timestamp and source-tool checks, `quality_reason`, `week4_strict_eligible`, `brian_pause_s`, `corrected_gap_proxy_s`, and auxiliary context/model fields for offline auditing only. Check the file schema before using any additional fields.

### Important validity limits

- **These are not observations of GPU KV-cache residency.** The target estimates between-round waiting time from TraceLab timestamps, not the original inference server's cache allocation or scheduler state.
- The strict benchmark is *selected with hindsight* to check the integrity of records. It is suitable for an initial predictor benchmark, **not representative of the entire workload**.
- Claude strict coverage is **88.67%** of original tool-pause rows; Codex is **59.48%**. Among originally usable Codex tool pauses, **13.17%** of strict records versus **22.78%** of excluded records exceed 10 seconds. Therefore evaluate and report excluded cases and tail coverage.
- Do **not** use original next-round-associated `n_tools`, `tool_names`, `tool_input_chars`, or retrospective episode/quality flags as decision-time prediction inputs; some were matched from future tool results.
- Brian's `pause_s` and the recomputed endpoint proxy agree in the first run (no >1-ms disagreements where comparable), but this is **same-formula reproducibility**, not independent proof of correct inference-stop timing.
- Treat complex/mixed/human waits separately; do not silently extend single-tool performance to all pauses.

## Rebuild from source

Run from the *TraceLab root* with TraceLab release **v0.0.1** and DuckDB/Python available. Prerequisites:

- `trace/syfi_coding_trace.duckdb` — TraceLab's source data.
- `group_work/pauses.parquet` — Brian's original `week3/build_pause_table.py` output.
- `group_work/tool_intervals.parquet` — Hangting's `analysis/validation/build_tool_dataset.py --step intervals` output.

From macOS/Linux:

```bash
cd ~/kv-week3-work/TraceLab
REPO=~/kv-week3-work/agent-kv-retention-hangting
python "$REPO/analysis/validation/build_pause_handoff.py"
python "$REPO/analysis/validation/check_handoff_bias.py"
```

Outputs are written initially to `TraceLab/group_work/`. To save the exact generated artifacts here on **`Hangting_week3`**, copy and commit:

```bash
git -C "$REPO" switch Hangting_week3
git -C "$REPO" pull --ff-only origin Hangting_week3
cp group_work/pauses_v2.parquet "$REPO/analysis/dataset/"
cp group_work/week4_pause_train.parquet "$REPO/analysis/dataset/"
git -C "$REPO" add analysis/dataset/
git -C "$REPO" commit -m "Add validated Week 4 TraceLab pause datasets"
git -C "$REPO" push origin Hangting_week3
```

On Windows PowerShell, use `Copy-Item` and the corresponding `$REPO` path. The raw database and all intermediate files remain outside the repository.

## Quick verification

With DuckDB installed:

```bash
python - <<'PY'
import duckdb
con = duckdb.connect()
for name in ('pauses_v2', 'week4_pause_train'):
    f = 'analysis/dataset/' + name + '.parquet'
    print(name, con.execute("SELECT COUNT(*) FROM read_parquet(?)", [f]).fetchone()[0])
print(con.execute(
    "SELECT provider, split, COUNT(*) AS rows FROM read_parquet(?) "
    "GROUP BY provider, split ORDER BY provider, split",
    ['analysis/dataset/week4_pause_train.parquet']
).df().to_string(index=False))
PY
```

Run the quick check from the repository root, not TraceLab. Expected initial totals: **357,161** and **219,465**. If changed, document the TraceLab version and generation-code commit before interpreting results.
